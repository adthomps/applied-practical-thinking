## Purpose

Public Applied Practical Thinking portfolio, learning, demonstration, and publication platform.

A pnpm monorepo containing a Vite and React public website, a separately deployed Cloudflare Worker API and AI subsystem, shared UI/config/knowledge packages, authored public content, and generators that publish an explicitly selected subset of canonical APT doctrine from the sibling apt-principles-agents repository.

- Repository type: `monorepo`
- Maturity: `active`
- Owner: APT
- Profile maintainer: Applied Practical Thinking maintainers
- Primary audiences: public APT learners, builders and architects, product and design teams, prospective collaborators and employers, APT maintainers and content authors

## Architecture

A browser application and Worker backend share workspace packages and publication contracts; authored product content and selected sibling doctrine are transformed into generated runtime assets for the public site.

- apps/web provides the Vite, React, and TypeScript public experience, routes, authored content, design doctrine, publication generators, and validation scripts.
- apps/worker provides the Hono-based Cloudflare Worker API, public feed assembly, AI and vector-search boundaries, and normalized content delivery.
- packages/ui, packages/config, and packages/knowledge provide shared presentation, token/config, and content/domain contracts.
- apps/web/scripts generates indexes, validation evidence, copied runtime content, and the curated public APT doctrine projection.
- apt-principles-agents remains canonical for reusable APT doctrine and agent assets; this repository owns its product implementation, public narrative, local exceptions, and deployment configuration.

- Runtime model: The web app runs in the browser from a Vite development or production bundle. The Cloudflare Worker runs independently at the API boundary and accesses Pages-hosted public assets plus a remote Vectorize index.
- Deployment model: Cloudflare Pages builds and serves apps/web from GitHub updates. apps/worker is deployed separately with Wrangler and GitHub Actions; the web and Worker communicate through an explicit VITE_API_BASE and PUBLIC_SITE_ORIGIN contract.

## Build and Run

Install the pnpm workspace, run the Vite web application and Wrangler Worker independently, generate publication assets before web builds, and deploy the two Cloudflare surfaces separately.

- Package manager: pnpm workspace commands at the repository root delegate to apps/web and apps/worker.
- Local server: pnpm dev starts the generated-and-validated Vite web experience; pnpm dev:worker starts the Cloudflare Worker separately.
- Build: pnpm build runs configuration checks, APT public-doctrine generation, validation reporting, content-index generation, public-copy generation, and the Vite production build.
- Deployment: Cloudflare Pages deploys the web output from GitHub builds; pnpm deploy:worker publishes the Worker through Wrangler.

## Distribution

- Cloudflare Pages builds and serves the public Vite application.

## Constraints

- Do not edit apps/web/public copied content or generated indexes as authored source.
- Do not redefine reusable APT doctrine locally; change apt-principles-agents and regenerate the approved public projection.
- Use semantic design tokens rather than raw color values in application components.
- Keep VITE_API_BASE and PUBLIC_SITE_ORIGIN explicit and aligned across Pages and Worker deployments.
- Preserve Worker-backed public feed contracts for Labs, Proof, and Insights.

- Deploy the Worker before rebuilding Pages when runtime contracts or environment configuration change.
